# Требования: SpeedReader для Zed

> Описание проекта: Расширение для Zed editor, реализующее SpeedReader — всплывающий поп-ап для быстрого чтения текста методом RSVP. Пользователь активирует его в открытом буфере, слова показываются по одному с выделенной центральной буквой. Скорость и цветовая схема настраиваются. При паузе редактор фокусируется на позиции чтения. Основная логика на Rust, GUI — через механизмы расширений Zed.

## 1. Базовое чтение (RSVP)

### 1.1 Отображение слов RSVP
- **Формулировка**: Система должна отображать текст из открытого буфера Zed слово за словом, с выделенной центральной буквой, согласно методу RSVP (Rapid Serial Visual Presentation).
- **Обоснование**: Основная функция SpeedReader — быстрая последовательная презентация слов для ускорения чтения.
- **Критерии приемки**:
  - Слова отображаются по одному в центре всплывающего окна
  - Центральная буква каждого слова выделяется цветом/стилем
  - Анимация/переход между словами плавный, без мерцания

### 1.2 Запуск из буфера
- **Формулировка**: Система должна запускаться из активного буфера Zed, захватывая выделенный текст (или весь буфер при отсутствии выделения).
- **Обоснование**: Пользователь работает с открытыми файлами и не должен покидать редактор.
- **Критерии приемки**:
  - Команда активации вызывает поп-ап с текстом из текущего буфера
  - Если есть выделение — используется только выделенный текст
  - Если выделения нет — используется полный текст буфера

## 2. Позиционирование и навигация

### 2.1 Поп-ап оверлей
- **Формулировка**: SpeedReader отображается в виде всплывающего окна (popup/overlay) поверх редактора, не переключая контекст пользователя.
- **Обоснование**: Пользователь должен оставаться в среде редактирования.
- **Критерии приемки**:
  - Окно появляется поверх редактора, не сдвигая его
  - Окно можно перемещать или оно занимает оптимальную позицию
  - Окно не блокирует весь редактор (частичная прозрачность или компактный размер)

### 2.2 Синхронизация позиции
- **Формулировка**: Система должна отслеживать, какое слово читается, и сохранять соответствие с позицией в оригинальном тексте.
- **Обоснование**: При паузе пользователь должен видеть, где находится читаемый фрагмент.
- **Критерии приемки**:
  - Позиция чтения сопоставлена с исходным буфером (индекс слова, строка, колонка)
  - При движении по тексту позиция обновляется

## 3. Управление чтением

### 3.1 Пауза и возобновление
- **Формулировка**: Пользователь может приостановить и возобновить чтение в любой момент.
- **Обоснование**: Контроль темпа чтения.
- **Критерии приемки**:
  - По нажатию клавиши (например, Space) чтение приостанавливается
  - Повторное нажатие возобновляет с того же слова
  - Визуальный индикатор состояния (чтение/пауза)

### 3.2 Отмена и фокус на позицию
- **Формулировка**: При отмене (cancel/close) SpeedReader должен закрыть поп-ап и переместить курсор редактора на текущую позицию чтения.
- **Обоснование**: Ключевое требование — не искать позицию вручную после чтения. Пользователь должен сразу редактировать.
- **Критерии приемки**:
  - По Escape или кнопке закрытия поп-ап исчезает
  - Курсор в редакторе перемещается на слово, на котором остановилось чтение
  - Редактор прокручивается к этой позиции (если необходимо)

### 3.3 Пропуск вперед/назад
- **Формулировка**: Пользователь может перемотать чтение на несколько слов вперед или назад.
- **Обоснование**: Уточнение позиции чтения без полного перезапуска.
- **Критерии приемки**:
  - Стрелки влево/вправо или кнопки перемотки сдвигают позицию на N слов
  - N настраивается (например, 5 слов по умолчанию)

## 4. Конфигурация

### 4.1 Скорость чтения (WPM)
- **Формулировка**: Пользователь может настроить скорость чтения в словах в минуту (WPM).
- **Обоснование**: Разные документы и предпочтения требуют разной скорости.
- **Критерии приемки**:
  - Регулятор WPM с диапазоном (например, 50–1000 WPM)
  - Значение по умолчанию: 300 WPM
  - Значение сохраняется между сессиями (в настройках расширения)

### 4.2 Цветовая схема
- **Формулировка**: Пользователь может настроить цветовую схему поп-апа (фон, текст, акцент центральной буквы).
- **Обоснование**: Визуальный комфорт при длительном чтении.
- **Критерии приемки**:
  - Настраиваются: цвет фона, цвет обычного текста, цвет центральной буквы
  - Минимум 2 предустановленные темы (светлая, темная)
  - Настройки сохраняются между сессиями

### 4.3 Размер шрифта
- **Формулировка**: Пользователь может настроить размер шрифта в поп-апе.
- **Обоснование**: Комфортное чтение на разных экранах.
- **Критерии приемки**:
  - Регулятор размера шрифта
  - Значение сохраняется между сессиями

## 5. Технические требования

### 5.1 Основная логика на Rust
- **Формулировка**: Вся базовая логика SpeedReader (RSVP-движок, управление позицией, конфигурация) должна быть реализована на Rust.
- **Обоснование**: Rust — приоритетный язык в проекте. Производительность, типобезопасность, WASM-компиляция.
- **Критерии приемки**:
  - RSVP-движок на Rust (разбивка на слова, синхронизация с буфером)
  - Логика конфигурации и сохранения настроек на Rust
  - GUI-часть может использовать механизмы расширений Zed

### 5.2 Расширение Zed
- **Формулировка**: Система реализуется как расширение для Zed editor, следуя его API расширений.
- **Обоснование**: Интеграция с платформой Zed.
- **Критерии приемки**:
  - Расширение устанавливается через `zed: extensions`
  - Использует Zed Extension API для доступа к буферу, редактору, командам
  - Сборка через `cargo build --target wasm32-wasi`

### 5.3 Производительность
- **Формулировка**: RSVP-чтение должно работать без задержек и пропусков кадров при стандартных скоростях (до 1000 WPM).
- **Обоснование**: Плавность критична для восприятия RSVP.
- **Критерии приемки**:
  - Переключение слов происходит точно по таймингу WPM
  - Нет заметных задержек (джиттер < 16 мс)
  - Работа с документами до 10 000 слов без проблем с производительностью
